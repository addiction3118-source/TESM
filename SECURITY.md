# Безопасность BlackArachnia

Документ описывает модель угроз, реализованные меры и рекомендации по
безопасному развёртыванию.

## Что и как защищено

| Данные | Где хранятся | Защита |
|--------|--------------|--------|
| API-ключи (Groq/Gemini/OpenAI) | `.keys.enc` | AES-256-GCM, ключ из пароля через PBKDF2-HMAC-SHA256 (200 000 итераций) |
| Мастер-пароль «Запомнить меня» | ОС-хранилище (keyring) | Windows Credential Manager (DPAPI) / macOS Keychain / Secret Service; срок жизни (TTL) |
| Токен агента | вводится в сессии, не сохраняется на диск | — |
| Telegram-токен/chat_id | `.env` (в `.gitignore`) | файл вне репозитория |

Секретные файлы (`.env`, `.keys.enc`, `blackarachnia.db`, `blackarachnia.log`)
перечислены в `.gitignore` и не попадают в репозиторий.

## Реализованные меры

- **Шифрование API-ключей** паролем (см. `keys_store.py`).
- **«Запомнить меня» через keyring** (см. `session_store.py`): мастер-пароль
  лежит в защищённом хранилище ОС, а не в файле проекта; по истечении TTL
  (`config.SESSION_TTL_HOURS`) пароль запрашивается снова. Старый небезопасный
  файл `.ba_session` (XOR-обфускация) удаляется автоматически.
- **`/exec` на агенте требует токен** (сравнение в постоянном времени
  `hmac.compare_digest`), есть лимит размера тела и список заблокированных
  деструктивных команд. Без заданного токена удалённое выполнение отключено.
- **Кнопка «Войти без ключей»** управляется флагом `config.ALLOW_SKIP_KEYS`
  (для локального инструмента включена; выключите при выставлении в сеть).

## Известные ограничения

- **Канал агента не шифрован.** `agent.py` отдаёт данные по обычному HTTP:
  токен `/exec` и вывод команд идут по сети в открытом виде. Эндпоинты
  `/metrics` и `/processes` доступны без токена (раскрытие метрик).
- **Локальный доступ к файлам.** Любой пользователь с полным доступом к
  машине, где запущена панель, потенциально может добраться до расшифрованных
  данных во время работы приложения — это неустранимо без аппаратного модуля.

## Рекомендации по безопасному развёртыванию

Не выставляйте порт агента (9999) напрямую в недоверенную сеть. Шифруйте
трафик одним из способов:

1. **SSH-туннель** (проще всего). Агент слушает только localhost на сервере,
   панель ходит через туннель:
   ```bash
   ssh -L 9999:localhost:9999 user@server
   ```
2. **WireGuard / VPN** между машиной с панелью и наблюдаемыми серверами.
3. **TLS-reverse-proxy** (nginx/Caddy) с сертификатом перед агентом.

Дополнительно:

- Запускайте агент под отдельным непривилегированным пользователем (не root).
- Файрволом ограничьте доступ к порту агента только адресом панели.
- Используйте длинный случайный `--token`.
